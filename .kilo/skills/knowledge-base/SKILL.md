# knowledge-base · 学科知识库的读写

结构和格式在 `knowledge-base/README.md` 和 `knowledge-base/格式/*模板.md`——**先读它们**。本技能只讲怎么做。

## 1. 先定位（体系意识）

任何读写之前，先落到具体专题目录：

1. **学段**：`学生档案.md` 的年级；不明先问
2. **学科**：读 `knowledge-base/<学段>/<学科>/index.md`，看板块 → 专题清单
3. **专题目录**：`knowledge-base/<学段>/<学科>/<板块>/<专题>/`

一个条目一个文件：`知识-<概念>.md` / `考点-<考点>.md` / `坑点-<坑>.md`。
`index.md` 是骨架清单——专题后面还没有文件的也列着（那些就是待补的）。

板块/专题在 `index.md` 里找不到 → **别自己造**，用学生自己的说法讲，把缺口记下来。

## 2. 讲题前：取口径

和 `tutor` §4 的侦察一起做：

1. 按 `index.md` 定位到板块/专题，再在专题目录里 grep。**`别名` 要一起搜**——学生口语、题库写法、讲义用词可能都不是标题里那个词
2. 有 → **沿用里面的判据、流程、符号**，同一考点前后必须一致
3. 缺 `前置` 指向的条目 → 他卡住很可能就卡在那儿：先补那一层，别在这条上反复讲
4. 读完能答就答。**知识库是口径来源，不是讲义**——不要把库里的条目倒给学生听

## 3. 讲完：沉淀

**只写"可复用、会重复出现"的**。一次最多 3–5 条；写完**不问**、也不在对话里宣讲（学生问起再说）。

写哪一层，看这条线索是什么：

| 线索 | 写成 | 认法 |
|---|---|---|
| 一个概念说不清 | `知识-` | "是什么"——定义、来源 |
| 一条可迁移的判断 | `考点-` | "怎么判"——判据、流程 |
| 一次可复现的翻车 | `坑点-` | "哪儿错"——错法、正解 |

**坑点还是缺口**：错因是**可复现的陷阱**（换个人也这么错）→ 写坑点；是他**自己没学会** → 那是缺口，走 `学习数据/`，**不进知识库**。拿不准就当缺口。

**写之前先查重**：用 `别名` + grep 搜同义条目；已有就在原文件上补，不新建第二条。

frontmatter 只填向上依赖（反向 grep 就有，别写两遍）：考点写 `知识`/`前置`，知识写 `前置`，坑点写 `考点`。
新建了**该专题第一个条目** → 把 `index.md` 里那一行打勾。

## 4. 老师给资料时

1. **原件先归档**：文件/图片放 `knowledge-base/<学段>/<学科>/原始/`，图片命名 `讲义-YYYYMMDD-序号.扩展名`
   ⚠️ 别和学生题图混——学生题图走 `学习数据/图片/`
2. **切分**：按考点/概念拆块，别整篇照搬
3. **逐块写入**：对得上现成 `考点-`/`知识-` 的补进去；对不上 → **问老师归哪个板块/专题**，不自己造
4. **冲突**：与已有条目冲突 → 以讲义为准，但**把改了哪一条报出来**；两份讲义互相冲突 → 不猜，问老师
5. **汇报**：新增/修订了哪些文件、各几条、哪些没找到归属

资料大就分批，做完一批报一批。

> `资料/`（旧模型，一章一文件）正在往本知识库迁移，暂时两边都在。

## 5. 体检

说"看看知识库"时，报这四类（**只报，不擅自改**）：

- **断链**：`前置`/`知识`/`考点` 指到的条目不存在——关联是单向的，没人守就容易烂
- **孤儿**：没有任何 `考点-` 在 `知识` 里引用它的 `知识-`（挂了没人用）
- **同名不同义**：同一个 `别名` 挂在多个条目上
- **空专题**：`index.md` 里有、目录下没条目的

# 题型体系维护

本技能负责让题型体系在真实题目和教学反馈中逐步生长，同时防止单道偏题、错误答案或 AI 联想进入学生主线。

本技能中的层级含义：

- **考点或设问类型**：某个大题型内部的分类，例如语法选择中的“名”，或阅读理解中的“推理判断”；
- **独立题型**：有自己完整任务形式和作答流程的大类，例如语法选择、完形填空、阅读理解。阅读题干换一种问法通常只是设问变化，不是新的独立题型。

出现以下任一情况时使用：

- 一道来源可靠的题无法由现有考点或流程稳定解释；
- 同一种新信号、新设问或新断点在不同材料中反复出现；
- 现有步骤会让多名学生产生相同误解；
- 维护者明确要求增加、合并、拆分或修订考点、方法、题型或流程。

普通错题能够由现有资料解释、学生只是没有执行已有步骤，或只有一道来源和答案均不确定的题时，不启动正式准入。

来源不足的单题若能自然归入已有内容，不登记候选；只有它疑似暴露真实体系缺口、以后值得继续追踪时，才在说明缺失证据并获得确认后登记为“待核验”。

## 使用前读取

先读取：

1. `题型/` 中当前题型的 `资料/` 目录下的考点地图、做题流程和相关考点文件；
2. `题型/README.md`；
3. `原维护仓库的 `维护/候选项.md`（未随本工作区分发）` 和 `原维护仓库的 `维护/决策记录.md`（未随本工作区分发）`；
4. 若候选来自学生表现，只读取与该问题有关的学生记录。

不要为了判断一个候选而一次加载所有题型资料。

## 学习处理与体系维护分轨

学生正在做题时，先完成学习闭环，不把课堂变成资料维护会议：

1. 核实当前题目、上下文、答案和来源是否足以讨论；
2. 只解释解决当前题目所需的最小知识或方法；
3. 若规则尚未确认，明确称为“候选解释”或“待核验情况”，不说成通用规律；
4. 不据此批量出题，不把学生在该题的表现直接判为稳定能力缺口；
5. 本轮学习结束后，再说明是否值得登记候选，并在用户确认后写入。

普通学习请求不自动授权修改公共题型资料。公共资料变更须维护者确认；学生状态按该题型 AGENTS 的记录规则执行。

## 公共资料整理模式

用户说“收集、整理、归档模板或素材”时，默认进入“只整理用户提供内容”模式：可以分类、去重、纠错、统一格式和补充来源字段，但不得自行新增模板、例题、话题素材或教学结论。

只有维护者明确选择以下模式之一时才扩大范围：

- **允许提出待确认建议**：助手新增内容只进入候选或建议区，不进入学生直接使用的正文；
- **允许正式扩充**：仍需遵守本技能的证据、准入、边界和联动规则。

模式不明确时保持默认，不以“让资料更完整”为理由预填内容。

## 第一步：完整保留问题

候选记录至少要能回答：

- 哪个题型、哪道题或哪种学生卡点触发了它；
- 题目来源、答案来源和可靠程度；
- 现有体系在哪个具体位置无法处理；
- 当前只为学生解决到了什么程度；
- 下一步还需要什么证据。

引用已有材料时优先记录文件和题号，不为维护方便大段复制受版权保护的原文。缺少必要上下文、选项、答案依据或来源时，状态只能是“待核验”。

## 第二步：先分类，不急着新建

按下面顺序判断：

| 分类 | 判断标准 | 默认去向 |
| --- | --- | --- |
| 已有内容的新外观 | 识别信号或包装变化，但仍调用同一知识和流程 | 给原考点补“考点特征、例题或易错外观” |
| 已有考点的边界 | 主体规则不变，只多了适用条件、反例或低频例外 | 补原考点的“边界/特殊情况”，不改初学主线 |
| 已有流程表述问题 | 流程本来能处理，但步骤含糊、顺序不清或容易误解 | 澄清原步骤，必要时增加对照说明 |
| 新的通用方法或步骤 | 多类题都会重复调用一个目前缺失的动作 | 更新该题型的做题流程，而不是新建知识考点 |
| 真正的新考点或设问类型 | 有独立识别目标、独立证据或知识要求，以及可复述的判断流程 | 建立新考点文档并更新考点地图 |
| 真正的新题型 | 任务形式、能力目标和完整作答流程均与现有题型不同 | 准入后先登记 `题型/README.md`，形成稳定框架后再建专项 Skill |
| 题目或结论存疑 | 来源、答案、上下文或规则互相冲突 | 保持待核验，不进入资料库正文 |

表面形式新不等于新考点。能自然归入已有考点并沿用同一决策流程时，优先完善原文档；不要靠不断新建文件解决分类问题。

若分类后确认它完全属于已收录内容，就退出维护流程并转回对应专项 Skill。学生仍可按当前目标和已学台阶练习该已有内容；这些练习用于学习，不用于证明一个新分类成立。

## 第三步：通过准入门槛

先检查以下条件：

1. **来源可靠**：题目和答案有可核验来源，或结论有可靠语法、考试材料或教学证据支持。
2. **不是偶发现象**：在多个彼此独立的可靠题目或学生案例中出现；或者有一份明确的权威依据和至少一个可靠实例。重复转载同一道题不算多份证据。
3. **现有体系确实不足**：已经检查相关考点和流程，不能通过澄清旧规则自然覆盖。
4. **可以操作**：能够写出识别信号、适用条件、最短判断步骤和答案证据；只有“有时凭语感”不能准入。
5. **有教学价值**：加入后能改善一类题的判断或卡点诊断，而不是只解释一道题。
6. **边界明确**：能标注适用学段、题型、考频、难度、前置知识和默认停止点，不会无故抬高初学要求。

准入强度按影响范围递增：

- **只补一个新问法或可靠例题**：一个来源和答案都可靠的完整实例即可，但只能作为例子，不能从中概括新通则；
- **增加边界或特殊情况**：需要明确规则依据，或多个独立可靠实例，并标出触发条件和低频属性；
- **修改主流程、新增方法、新建考点或题型**：必须满足上面的完整门槛，并用旧题、新题和反例做回归检查。

证据不足但值得继续观察时，保留在 `原维护仓库的 `维护/候选项.md`（未随本工作区分发）`。不得为了让体系显得完整而降低门槛。

## 第四步：作出一种明确决策

候选最终只能进入以下一种主要结果：

- **合并到已有内容**：补充特征、例题、边界或表述；
- **列为特殊情况**：保留按需入口，不进入默认教学主线；
- **更新通用流程**：新增或调整会改变学生作答顺序的步骤；
- **新建考点**：确有独立识别目标和判断流程；
- **新建题型框架**：确有独立任务和完整教学流程；
- **继续观察**：价值可能存在，但证据仍不足；
- **不纳入**：题目错误、重复、过于偶发，或会让体系变差。

决定“不纳入”不等于删除记录。将理由写入 `原维护仓库的 `维护/决策记录.md`（未随本工作区分发）`，避免以后重复争论同一问题。

## 正式修改前与维护者确认

完成分类和核验后，先用下面的短格式提交建议：

```markdown
- 候选：
- 当前分类：
- 可靠证据：
- 与现有体系的关系：
- 建议结论：合并 / 特殊情况 / 更新流程 / 新建 / 继续观察 / 不纳入
- 教学边界：是否进入初学主线，默认停在哪一层
- 拟修改文件：
- 暂不修改的部分：
```

维护者在看到分类、证据状态和拟修改文件后确认，才正式修改。此前“直接加进去”“自动完善”等概括性要求只授权开展调查，不能替代这一步确认；确认本身也不能跳过证据门槛。若维护者提供了新证据，先重新判断。

## 第五步：按影响范围联动更新

正式更新采用“小事务”方式：先列出将修改的文件，修改后一起核对，避免只改一处造成地图、流程和 Skill 不一致。

### 新建或调整考点

按实际影响更新：

1. 对应考点正文；
2. 题型资料目录中的考点地图；
3. 若学生作答顺序改变，更新题型资料目录中的做题流程和版本记录；
4. 若教学顺序或前置改变，更新题型资料目录中的学习路径；
5. 若成为资料库正式内容，更新 `题型/README.md`；
6. 若题型进度文件逐项列出考点，在用户确认后增加该项并标为“未评估”；不能倒推学生已经会或不会；
7. 只有可复用的教学行为改变时，才修改专项 Skill；不要把知识正文复制进 Skill。

新考点文档至少说明：适用学段、考频、难度或台阶、前置知识、识别特征、最短流程、重点、难点、特殊情况、默认停止点、例题或证据来源、维护记录。

### 新建或调整方法

方法要落在它真正改变的位置：

- 只帮助理解一个考点：写入该考点文档；
- 改变某题型的作答顺序：写入该题型资料目录中的做题流程；
- 影响该题型的教学诊断和反馈：同步修改专项 Skill；
- 多个题型共用：在 `资料/通用/` 维护参考；若会改变学生运行行为，必须同步受影响题型的本地规则，不能让题型工作区依赖父目录。

不要在考点地图、流程、Skill 和学生文件中重复维护同一段正文。

体系变化不自动改写既有学生能力结论。只有后续学习产生新证据时，才调整相应状态；单纯新增了一个考点，只能说明这个考点此前未评估。

## 第六步：验证后再关闭

修改完成后至少检查：

- 新旧分类是否互斥且没有明显漏项；
- 学生能否根据新增信号找到正确考点或方法；
- 新步骤能否处理候选证据，同时不破坏原有典型题；
- 初学主线、考频、台阶和默认停止点是否仍然清楚；
- 相关链接、索引、版本和 Skill 校验是否通过。

验证通过后，将候选从 `原维护仓库的 `维护/候选项.md`（未随本工作区分发）` 移入 `原维护仓库的 `维护/决策记录.md`（未随本工作区分发）`，写明日期、结论、依据、影响范围和修改文件。尚未通过就保持候选状态，不用“暂时应该可以”关闭。

## 已纳入内容后来被推翻

出现更可靠的新证据时，重新建立候选并链接原决策。修订正文和版本记录，说明旧结论为何不再适用；不要静默删除旧规则，也不要让已撤回内容继续作为出题得分点。

## 绝对不做

1. 不因一道偏题直接新建考点；
2. 不把 AI 自己能解释当作可靠来源；
3. 不把学生跳过已有步骤误判为流程缺失；
4. 不把低频例外塞进初学主线；
5. 不用尚未准入的候选批量讲解、出题或评估学生；
6. 不在未经说明和确认时修改公共题型资料；
7. 不为了保留旧体系而强行把真正的新证据塞进不合适的分类。
